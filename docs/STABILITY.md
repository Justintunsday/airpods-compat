# 当前稳定性与保守策略

更新日期：2026-09-27。此文描述当前代码；`ANALYSIS.md` 保留早期研究和实现历史。

## 默认行为

首次安装只补充缺失的名称，保留系统已有的非空名称。UARP 默认关闭，范围默认 `core`。
既有配置中明确的布尔开关值保留；升级不会悄悄覆盖用户配置。可在 App 关闭总开关或
UARP 开关，重启用户空间后生效。损坏/无法读取的偏好文件会使 tweak 停止初始化；
App 不会覆盖该文件，应先备份并修复。

Swift FeatureContent 借用已暂停，旧 `BorrowProfile` 不生效。旧实现以
`id (*)(uint32_t, id)` 转调 Swift 私有函数，尚未验证 Swift 的隐式上下文参数、
返回值布局和所有权。单纯找到符号、构建通过或协议 existential 布局一致，都不足以
证明转调 ABI 正确。因此当前不安装该 hook，设备使用系统原有的功能页。

恢复借用前需要：确认目标构建的完整函数调用约定，用正确 ABI 的桥接验证实参、
返回值与生命周期，并在设置、配对服务上完成真实设备的稳定性回归。

## 配置与注册

- 对开关、注册范围、型号标识、PID、备选型号与抽象基类做类型和范围校验。
  重复 PID、重复型号、非法标识或异常结构使整份注册表失效，避免部分错误注册。
- 只允许四个已记录的抽象基类，不尝试具体型号 fallback；抽象基类缺失时跳过。
  初始化失败、类名冲突或注册异常时立即停止，保留进程守护标记。
- 调用 manager getter 和注册 API 前检查 Objective-C 返回类型与实参类型。
- 注册仍限于四个配件守护进程，SpringBoard 不再注入；iOS 27+ 跳过所有兼容改动。
- 标记位于包的 Application Support 目录，名为
  `.registration-in-progress.<进程名>`。默认不自动删除失败残留，不反复尝试。
  先关闭 UARP、保存日志并确认失败原因，再人工处理对应进程的标记。

## 诊断与扫描

真机自检只检查系统类与型号表，不创建动态配件类、不向系统管理器注册。
模拟器使用独立桩类验证注册机制，不能据此判断真机 CoreUARP 接受新型号或支持固件更新。

蓝牙属性探测优先使用 KVC 的标量装箱；fallback 通过实际方法签名和 NSInvocation
读取对象或明确支持的整数类型。结构体、带实参方法和异常均跳过，避免把 BOOL/PID
当作对象指针。字符串数字明确区分十进制与 `0x` 十六进制，并拒绝剩余字符。

BLE 扫描由用户启动，20 秒后停止；离开页面、蓝牙不可用或用户停止后不自动重新开始。
附近缓存最多 128 个设备，只保留最近 30 秒内的广播记录（在新广播到达时清理）。

## 验证边界

CI 检查 App 模拟器回归、未签名 IPA，以及 rootless/rootful deb 的编译和打包。
安全策略测试使用生产代码共享的校验和私有方法读取函数。
这些检查不证明真机设置页、ANC、电量、手势、UARP 注册或固件更新有效。
当前仍需要按系统构建、设备 PID、日志和实际页面表现逐项记录真机证据。
